The six figures the gold layer answers for

Each tile names what it measures, the figure, and one line on how to read it. Charge-side figures come from gold.fact_transactions; claim-side figures come from silver.claims, which this repository never promotes to a gold fact.

Charged against collected, by service month

gold.fact_transactions

The gap between the two lines is money billed but not received. Hover any month for its collection rate and transaction count. Service dates span 1 Jan – 6 Nov 2024, so November is a partial month and its points are drawn hollow — the drop is the calendar, not a collapse in billing.

select date_trunc('month', ServiceDate), sum(Charge_Amt), sum(Paid_Amt) from gold.fact_transactions group by 1 order by 1

What happened to the 20,000 claims

silver.claims

Claims are grouped by what they mean for the revenue cycle: settled needs nothing, in flight is waiting on the payer, and needs rework has to be corrected and resubmitted before it can ever be collected. The five raw status values sit underneath.

select ClaimStatus, count(*) from silver.claims where is_current and not is_quarantined group by 1

Charges by department

+ dim_department

Top 10 of 20 departments by charged amount. Both hospitals run the same 20 departments, so each bar sums its hosa and hosb rows. Hover for that department's collection rate.

fact_transactions f join dim_department d on f.FK_DeptID = d.Dept_Id group by d.Name

Claims by payer type

silver.claims

Who is being billed. Self-pay has no insurer behind it, so it is where collection risk concentrates — on a real feed this bar is the one to watch, and here it is a third of all claims.

select PayorType, count(*), sum(ClaimAmount) from silver.claims group by 1

Patients by age band

gold.dim_patient

Age from DOB as of today, across both hospitals. Bands are ordered, so the fill darkens as the band rises — the colour repeats the axis rather than adding a second meaning.

select DOB from gold.dim_patient where is_current and not is_quarantined

What ran when this page loaded

A production platform runs these stages on Spark against cloud storage, orchestrated by a scheduler. This page runs the same rules in the browser — the CDM column mapping that reconciles the two hospitals, the quarantine predicates, the surrogate keys, and the is_current and not is_quarantined filter into gold — over the CSVs in datasets/, so the whole pipeline is inspectable without any infrastructure.

medallion architecture

Config-driven ingestion

datasets/load_config.csv

ADF reads this control table with a Lookup activity and runs one Copy activity per row inside a ForEach. Changing an ingestion means editing a row here, not editing a pipeline. loadtype picks full reload against incremental, watermark names the column an incremental load compares, and is_active = 0 switches a table off — which is why this table lists tables the run above did not read.

The gold layer is a star

One fact table of billed transactions, surrounded by the dimensions that describe them. Every surrogate key appends the data source, so two hospitals can issue the same IDs without being merged. The percentage on each arm is how often that join actually finds its dimension row.

What this data cannot support, and why

The silver quarantine predicates run on every row, and this run also checks every foreign key in the fact table against its dimension. Findings are ordered by severity, each with the count behind it and what fixing it would take. Two of them are the reason this dashboard is missing metrics an RCM dashboard normally leads with.
